# 项目强制架构约束

本文件适用于整个仓库。任何后续开发开始前，必须按顺序完整阅读：

1. `项目开发说明.md`：了解玩法目标、当前实现、跨电脑交接、今日改动和下一步任务。
2. `架构规范.md`：了解强制依赖方向、领域边界、存档规则和禁止事项。

两份文档必须同时遵守；不能只读其中一份。开始修改前还要运行 `git status --short`
确认用户已有改动，并运行 `npm test` 建立当前基线。不得因为工作区存在未提交改动而重置、
覆盖或删除它们。

## 文件规模

- 不以文件、类或方法的行数作为禁止开发或检查失败的条件。
- 文件可以超过 1186 行；只要内容属于同一职责、内部结构清楚、依赖方向正确并且便于验证，就是允许的。
- 是否拆分由职责边界、修改频率、复用需求和测试难度决定，不能仅凭行数决定。
- 大文件可以继续维护，但禁止把无关业务为了方便堆进同一个类。

## 职责边界

- `scenes/` 只负责 Phaser 生命周期、资源加载和模块装配。
- `ui/` 只负责绘制、输入和用户反馈。
- `domain/` 负责游戏规则，禁止依赖 Phaser、DOM、场景或 UI。
- `core/` 负责存档、模板仓库和基础配置，禁止反向依赖 UI/场景。
- 功法、法术、商店、背包、法宝必须是独立模块，禁止通过另一个页面的方法获取数据。

## 修改要求

- UI 不得直接实现交易、配装、伤害或存档迁移规则。
- 跨模块通过服务接口、ID 和普通数据对象通信。
- 新增领域规则必须配套纯 JavaScript 测试或至少可重复的冒烟验证。
- 禁止重复 class 方法、隐式覆盖和在 `render()` 中修改存档状态。
- 当前统一验证命令是 `npm test`；完成改动后还要对新增 JavaScript 执行语法检查。
- 当前接手顺序和未完成任务以 `项目开发说明.md` 最后一章为准，旧日期记录只作历史参考。
